## PALF-Vision AI: Integration of Image-Derived Texture Thresholds

### 1. Project Overview

Integrate the experimentally derived texture thresholds into the existing PALF-Vision AI web application.

The application classifies cleaned pineapple leaf fiber (PALF) bundles into three cleaning grades:

- Excellent
- Good
- Fair

The system currently uses a ResNet-50 model for image classification and a separate visual-analysis module for measuring color and texture.

The objective of this task is to add a **threshold-based texture assessment** using the texture features and candidate thresholds derived from the 54-image inspector-labelled dataset.

The texture assessment must be displayed alongside the existing CNN classification results.

Follow these requirements throughout implementation:

1. Do not retrain, replace, or modify the existing ResNet-50 model.
2. Do not modify the existing CNN weights, model architecture, or preprocessing pipeline.
3. Do not change the existing Excellent, Good, and Fair CNN classification logic.
4. Do not modify the moisture sensor calculation or ESP32 communication.
5. Do not remove or break existing color analysis.
6. Do not change existing IndexedDB history records or their retrieval functionality.
7. Preserve compatibility with the current Next.js 15, React 19, JavaScript, and Python backend.
8. Do not introduce unnecessary dependencies. Prefer the existing OpenCV and NumPy implementation.
9. Do not interpret image-derived texture measurements as direct measurements of tactile softness or physical roughness.
10. Do not invent numerical thresholds if they are missing from the provided threshold-study files.

### 3. Dataset and Threshold References

Use the following research outputs as the source of the candidate thresholds:

- `palf_texture_features.csv`
- `palf_candidate_texture_thresholds.csv`
- `palf_threshold_rule_details.csv`

The dataset contains 54 images:

| Cleaning grade | Number of images | Texture label | PNS reference |
|---|---:|---|---|

### 4. Texture Features to Implement

Implement the following features using the same formulas, parameter settings, and image-processing approach used in the threshold-study notebook.

#### A. Structure Tensor

Implement:

- Orientation concentration
- Orientation spread (degrees)
- Regional orientation concentration
- Regional orientation spread (degrees)

These features describe the consistency and variation of visible fiber directions within the bundle.

Use the same circular/axial orientation calculations from the notebook. Fiber orientations are equivalent modulo 180 degrees, so do not calculate their ordinary arithmetic mean without accounting for angular wrapping.

#### B. Gabor Filter Analysis

Implement:

- Gabor response anisotropy

Use the same filter-bank settings and response calculation as the notebook.

Ensure that the interpretation of the dominant Gabor filter angle is consistent with the actual visible fiber direction. Do not assume that the filter angle directly represents the fiber orientation.

#### C. GLCM

Retain the existing GLCM calculations:

- Contrast
- Homogeneity
- ASM (Angular Second Moment)
- Energy
- Entropy

Use consistent grayscale conversion, quantization, distance, symmetry, and direction settings between global and regional calculations.

Note that:

- ASM = sum of squared normalized GLCM probabilities.
- Energy = square root of ASM.

Do not label ASM as Energy unless the square root is applied.

#### D. Optional Supporting Features

Edge Density and Gradient Magnitude may remain available as supporting measurements if already implemented.

Laplacian Variance must remain an image-quality/focus measurement, not a texture grading feature.

### 7. Handling Uncertain or Invalid Results

The system must not force a texture prediction when the image cannot be analyzed reliably.

Return an appropriate status when:

- The fiber mask is empty.
- The fiber mask has insufficient coverage.
- The image is blurry or unsuitable.
- A required feature cannot be calculated.
- A required feature is outside the supported range.
- The threshold rule cannot be evaluated.

Use statuses such as:

- `available`
- `insufficient_image_quality`
- `insufficient_fiber_mask`
- `feature_calculation_failed`
- `threshold_not_available`

Do not substitute zero for a missing measurement. A missing value must remain null and must not accidentally satisfy a threshold condition.
